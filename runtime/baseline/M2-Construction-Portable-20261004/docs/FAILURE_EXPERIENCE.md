# 失败经验有条件复用：本轮候选

这版把真实失败留下来，再在后续任务条件一致时提供建议。建议不能批准执行，也不能把未知效果改成失败或成功。当前仅接两个明确入口：薄桥保存原回执之后的可选入档，以及新任务的 `prepare-context`。直接调用原 CLI、其他宿主和 C06 不在接入范围内。

## 基线与布局

`core/` 保持 33 成员结构。便携派生只改路径相关文档和两个测试文件，核心运行时代码保持来源 ZIP 字节；当前清单见 `CORE_CAPTURE.json`，原哈希见 `BASELINE.json`。薄桥仍检查这 33 个成员与完整目录清单。新增的宿主模块在外面的 `src/m2_construction/failure_experience.py`，不塞进旧核心目录，不把 33 成员检查放宽为 34。

调用者分别固定核心清单、原配置、Python、桥绑定、适配模块和会话描述符的 SHA-256。当前字节清单见 `CORE_CAPTURE.json`，历史来源见 `BASELINE.json`。这些材料不是生产 Root，也不是操作系统沙箱；测试私钥只在隔离测试进程内生成，不落盘。

## 两个接点

**失败入档。** 执行原薄桥 `command` 时，显式增加以下三个参数：

```
--experience-descriptor <当前会话描述符绝对路径>
--experience-descriptor-sha256 <描述符实际 SHA-256>
--experience-adapter-sha256 <适配模块实际 SHA-256>
```

不提供这组三参数，旧行为保持不变。原 `receipt.json` 先独占保存，再尝试入档。入档结果放在同操作目录的 `failure-experience.json`，入档失败不会修改原回执、退出码或原始输出，不会自动重试原操作。

入档核对原操作、签名范围、过程回执和日志的实际字节。`COMPLETED` 只表示操作有回执；测试自身的 `FAILED` 和非零退出码照原样保留。桥传输超时或操作未决继续标为效果未知，原因未知另列。不能凭错误文字猜根因。

**新任务准备。** 当前任务、授权和活动租约已由原机制建立后，显式执行：

```
python -B tools/native_b_runtime.py --binding <新任务桥绑定> --binding-sha256 <绑定SHA> prepare-context --experience-descriptor <新会话描述符> --experience-descriptor-sha256 <描述符SHA> --experience-adapter-sha256 <模块SHA>
```

它读取原 `OrchestrationStore` 状态，在原 `MemoryStore` 中建立新任务的建议引用，再经原 `EvidenceProjection` 和 `context_bundle` 构造上下文。它不签根、不签授权、不启动模型、不派发产品效果。输出恒为 `dispatch_allowed=false`；恢复结果为 `BLOCKED_UNKNOWN` 时，仍保留原未决操作 ID，不能用准备成功表示可执行。

## 描述符与证据边界

描述符采用严格的 `CK_FAILURE_EXPERIENCE_SESSION_1` 字段集合。实际可启动样例由同目录测试脚本生成，包含当前七字段绑定、节点、任务类型、明确相关依赖、前提、来源读取范围、历史材料的外部哈希锚、独立证明目录、撤销与冲突目录、上下文上限和当前到期时间。任务类型只接受 `TEST`、`BUILD`、`CODE_CHANGE`，不是模型自由填写的新能力。

当前描述符由受信调用者在外部传入精确哈希。相关依赖只接受显式模块、规则和接口的实际单文件指纹，不做全仓扫描或通用依赖推断。读取范围必须明确声明：当前项目的任务工作区、状态目录或当前 CLI 配置所在的公共输入目录；每个文件有字节上限，缺来源、越界、链接或哈希不符不会降级放行。这里的读策略是可信宿主回调，不能宣称隔离了任意本机进程。

经验文本只带允许的状态、来源引用、适用条件和有证据支持的主张。不默认复制环境、凭据、完整原请求或整段标准输出/错误。原日志继续按原权限留存并按需核对哈希。本功能不是秘密扫描或清洗工具，也不声称原审计材料不含敏感信息。

## 历史与当前引用

历史材料在 `history_root` 中以独占文件保存。重复登记同原回执只能复用字节完全相同的材料，不能覆盖。更正另写新版本和 `supersedes`，原记录保留。历史任务和旧授权仅作来源，不填入新任务当前绑定，也不能复活旧租约。

历史经验没有默认年龄期限。年龄、原授权已经到期或全仓无关文件改变不使它失效。仅在当前任务类型定位候选后，逐项比较相关模块、规则、接口和场景前提。相关变化只使对应经验待复核；缺证、篡改、撤销、冲突和缺前提各自给出排除理由。

原因默认未知；未验证的假设不会进入已核验的原因文本。确认原因需要外部固定的独立证明，明确验证范围、精确历史版本及对照与候选的支持文件。本轮明确支持 `CK_FAILURE_CONTROL_RESULT_1` 的真实测试对照：相同被跟踪输入、程序、参数、环境和超时条件下，控制非通过、候选通过，来自不同真实操作，并核对各自签名授权、过程回执和日志。这不是通用因果证明系统；源码诊断等其他独立证据可作为审计材料保留，本轮不会自行把它转换成测试对照。宿主逐文件重读并核对字节，不接受两个角色指向同一材料、自报 `verified=true` 或只提供一张哈希目录。历史独立验证与当次适用性验证分开。

新任务描述符中的 `historical_anchors` 由可信调用者固定每条历史材料的路径、实际哈希和大小。材料的作者不能通过同时改旧描述符和经验、重新计算哈希来自动更新这个外部锚。历史权限哈希另与原已签范围核对。这个本轮调用者锚不等于第三方长期不可重写存证；任意宿主管理员不在隔离声称范围内。

当前引用只使用 `COGNITION`。核验回调重读真实回执、历史来源、相关依赖和支持证明，不使用无条件返回真的检查器。核心的技能激活机制没有被调用。构造上下文前后均通过实际 `load_projection` 重新核验当前性；途中变更应拒绝输出旧建议。

匹配完成先独占保存 `matched-selection.json`，明确标为“已匹配、尚未经核心验证”，不能据此称为准备成功。核心随后拒绝时，原异常仍然生效，已选与排除理由留存，并尝试追加只含阶段和异常类型的失败记录；保存诊断失败也不能覆盖原拒绝。更正关系不合法或前版本值不是合法哈希时，仅排除该条材料，不能拖住其他有效经验。
