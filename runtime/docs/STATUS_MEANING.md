# 状态分别表示什么

同一个“通过”必须带阶段、对象和证据。本页解释含义，不是某次运行已经通过的声明；精确机器状态以本次命令 JSON 与原回执为准。

| 阶段或状态 | 可以说明 | 不能自动说明 |
|---|---|---|
| 无参数帮助 / `workflow` | 找到了入口和操作说明 | 环境可运行、项目资料完整 |
| `STARTUP_READY` | 本次环境、依赖及其覆盖的包文件检查通过 | 业务功能、跨平台验收或项目 PASS |
| `NEEDS_PROJECT_CONFIGURATION` | 环境检查已完成，尚未指定项目资料配置 | 已经理解项目或可以施工 |
| `CONTEXT_READY_FOR_REVIEW` / `PROJECT_CONTEXT_READY` | 来源登记与读取满足当前完整性条件，可以审阅资料 | 内容属实、语义冲突已解决、具备执行权限 |
| `PROJECT_CONTEXT_INCOMPLETE` | 已输出缺失类别、来源失败或声明冲突等问题 | 可以忽略缺口提升为事实 |
| `EXECUTION_ONLY_CONFIGURATION`（CONFIG_1） | 原基础执行阶段所需配置已装配 | 独审与 CEO 已装配或完成 |
| `INTERNAL_RETURN_CONFIGURATION`（CONFIG_2） | 含内部回交所需 reviewer 配置 | review 已实际执行、全链入口齐备 |
| `FULL_CHAIN_CONFIGURATION_PRESENT`（CONFIG_3） | 原全链入口所需四类 pin 配置齐备 | 任一审查/接受/发布阶段已通过 |
| `TEST_ONLY` | 当前使用测试信任域 | 生产 Root、真实业务发布授权 |
| `DEMO_COMPLETED` | 该次样例流程达到了自己的检查条件 | 当前业务项目成功或完整治理链成功 |
| `GRANTED` | 当前签署 Scope 已被登记 | 超出 Scope 的效果被允许 |
| TEST 的 `PASSED` | 指定命令在记录条件下通过 | 全部需求已覆盖、被测对象自然等于候选、独审完成 |
| `FROZEN` | 候选字节与测试/构建证据已形成绑定 | 候选已获独立批准 |
| `ATTESTED` | 当前候选的外部签署作者证明已被接受 | 独立审查已经完成 |
| 独审 GO / 局部裁决通过 | 指定候选与局部审查条件满足相应规则 | 整个父项目已验收或具备发布权限 |
| `INTERNAL_PARENT_ONLY` 回交 | 发生了受控的内部父级回交 | 可以对外发布 |
| CEO 的 `ACCEPTED` | 当前绑定证据满足 CEO 接受记录条件 | 已消费发布 lease 或人工用户已验收 |
| PRE 的 `PASS` | 此刻指定候选满足发布前只读裁决 | 已派发发布；该裁决本身 `dispatch_allowed=false` |
| release 的 `COMPLETED` | 对应受控效果已完成；重复查询可能仅返回历史效果 | 目标以后不会变化、所有环境都已部署 |
| POST 的 `VERIFIED` | 此次核对的目标字节与已完成效果相符 | 永久保证目标不变、业务需求无缺陷 |
| `BLOCKED` / `DENIED` / `FAIL` | 该次条件未满足或操作拒绝 | 后续可绕过入口、删除失败后重试 |
| `UNKNOWN` / `INDETERMINATE` | 效果或证据尚不能确定 | 操作肯定未发生、可自动换 ID 重放 |
| `NOT_RUN` | 该检查未执行 | 项目没有该测试、结果一定会失败或通过 |
| 人工审阅待定 | 还没有本次明确人工接受 | 可继承旧版本的人验 PASS |
