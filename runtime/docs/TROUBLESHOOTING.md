# 启动与接入排障

先保留失败命令、工作目录、解释器版本、退出码、完整输出和相关文件哈希。不要先改基线或跳过完整性检查。下表是排查入口，具体原因以本次原日志为准。

| 现象 | 下一步 |
|---|---|
| 找不到 Python / 版本低于 3.11 | 用 `python --version` 或 `python3 --version` 核对；选择实际安装的 3.11+ 解释器，在包外建立虚拟环境 |
| 找不到 `cryptography` | 用执行 `m2.py` 的同一解释器运行 `-m pip install -r requirements.txt`；不要把依赖安装到另一个环境 |
| PowerShell 把含空格路径拆开 | 可执行文件路径用引号并前置 `&`；每个路径参数分别加引号，参照 START_HERE |
| `doctor` 报包文件变化或清单不匹配 | 保留问题副本，和可信 ZIP 解压的新副本对照；不改清单把未知修改变成“正确” |
| AI 只会运行样例、不知道真实入口 | 从包根 README / AGENTS / START_HERE 开始，运行 `m2.py` 查看帮助；完整内核从 `kernel` 接入 |
| `start` 缺少项目资料 | 先用 `project-init` 指定实际来源，再 `start --project …`；启动器不会推测项目目标或自动搜全仓 |
| 来源不存在、哈希变化、状态过期或冲突 | 核查该来源当前版本与原登记依据；保留旧配置，经过审阅后建立新的索引或更新声明，不把重算哈希当作事实认证 |
| 来源路径、输出路径或链接被拒绝 | 使用实际绝对根目录、根内普通文件的相对路径；排除 `..`、通配符、链接与重解析目录，输出放到包外新路径 |
| `readiness` 拒绝配置/pin/hash | 回到可信操作者预先审核的配置与 pin，核对 schema、规范绝对路径和固定哈希；不要从请求临时计算“可信”哈希 |
| 只有 CONFIG_1，无法内部回交或 CEO 接受 | 基础执行配置本来不含完整链身份；由可信操作者装配所需 CONFIG_2/3，不能从样例生成后冒充独审已完成 |
| 迁移后配置或桥绑定失效 | 重新核对当前绝对路径、解释器字节、内核 capture 和配置哈希；旧机器的绑定不能直接沿用 |
| `sample` 输出已存在 | 保留该目录，选一个新的包外绝对路径；不要删除旧失败或覆盖原运行记录 |
| 样例中出现退出 7 的 FAILED 回执 | 原 flow01 会保留一次有意触发的失败，用于后续经验读取；核对最终 flow 结果及所引回执，不把这条原失败改为 PASSED |
| 命令超时、结果 UNKNOWN/INDETERMINATE | 先按原 operation ID 查询状态、核对实际文件与原回执；不能换 ID 自动再执行 |
| TEST 通过，但审查/验收未完成 | 按 WORKFLOW 补齐真实独审、接受和后续阶段；不以测试计数替代治理证据 |
| Maven 的 `-f` 指到另一份仓库 | 查明实际读取源码与冻结候选的关系，固定相同字节再验证；另一份工程通过不能证明当前候选通过 |

## 与可信版本对照

修复前选最近验收或发布的可信版本，记录版本标识、必要配置和输入。用相同前置操作、历史、数据范围、模型配置和输入对照；不能相同的条件明确列出。随机输出做少量同条件复测，不凭单次结果认定回归。

两版都复现，先按已有缺陷或此前漏测调查；只有候选可重复失败，检查版本差异；两版均未复现，只报告本轮未复现。先找日志中第一个可证实差异，再做对应的最小修复，保留原失败和回退点。

修复后完成同一用例的最短真实用户流程及必要影响检查。稳定通过的无关项目不反复重跑；未闭合问题单独登记，不借排障扩大授权范围。

## 平台限制

macOS/Linux 命令示例不等于实机验收。环境拒绝、路径差异或二次改造造成的行为需要实际 diff、配置与原日志才能定因；不能凭一份叙述断定某个操作系统或模型破坏了内核。

本包不是全局工具拦截器或 OS 沙箱。若进程可直接修改包、状态或发布出口，程序内的哈希与 Gate 不能替代宿主的可信隔离和权限部署。
